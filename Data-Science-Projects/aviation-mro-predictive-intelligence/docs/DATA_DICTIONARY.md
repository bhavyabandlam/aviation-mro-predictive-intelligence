# Data Dictionary

Field-level definitions for the Aviation MRO Predictive Intelligence Platform
(SRS §9, §10). Dataset licensing and provenance are in
[`DATA_SOURCES.md`](DATA_SOURCES.md).

Conventions:
- **PK** = primary key, **FK** = foreign key.
- SQLite types are `TEXT` / `INTEGER` / `REAL`; timestamps are ISO-8601 `TEXT` (UTC).
- Analytical Parquet tables use pandas dtypes.

---

## 1. Raw input — NASA C-MAPSS FD001

Whitespace-delimited, **no header row**, 26 columns
(`data/raw/extracted/fd001/{train,test}_FD001.txt`). The parser assigns canonical
names after verifying the column count (SRS §5.3).

| Position | Canonical name | Type | Meaning |
|---|---|---|---|
| 0 | `unit_id` | int | Engine/unit identifier |
| 1 | `cycle` | int | Operating cycle index |
| 2 | `setting_1` | float | Operational setting 1 |
| 3 | `setting_2` | float | Operational setting 2 |
| 4 | `setting_3` | float | Operational setting 3 |
| 5–25 | `sensor_01` … `sensor_21` | float | Sensor channels 1–21 |

**RUL labels** (`RUL_FD001.txt`): one value per test unit = remaining useful life
at the final observed cycle. Train targets are derived as
`RUL = max_cycle(unit) − cycle`, capped at `rul_cap` (default 125).

---

## 2. Engineered RUL features (`src/aviation_mro/features/rul_features.py`)

Generated by `engineer_features`; rolling statistics use **past-only** windows.

| Column | Type | Definition |
|---|---|---|
| `unit_id`, `cycle` | int | Engine and cycle keys |
| `op_setting_1`, `op_setting_2` | float | Operational settings (setting_3 excluded) |
| `rul` | float | Uncapped remaining useful life |
| `rul_capped` | float | `min(rul, rul_cap)` — model target |
| `<sensor>_<stat>_<window>` | float | Rolling statistic per informative sensor; `stat ∈ {mean,std,min,max,slope}`, `window ∈ {3,5}` (configurable). Example: `sensor_11_mean_5` |
| `cycle_norm` | float | Normalised engine age (optional) |

Constant sensors (1, 5, 10, 16, 18, 19) and raw sensor columns are excluded from
the model feature set. Feature order is fixed and recorded in the model card.

## 3. Synthetic business tables (SQLite, SRS §10)

Created by `src/aviation_mro/persistence/schema.py`. All synthetic rows are
labelled (`is_synthetic` where present) and generated with a fixed seed (42).

### `data_sources`
| Column | Type | Notes |
|---|---|---|
| `source_id` | TEXT PK | e.g. `DS-01`, `SYN-MRO-BIZ` |
| `title` | TEXT | Human title |
| `source_type` | TEXT | `nasa` / `synthetic` / `bts` / `reference` |
| `status` | TEXT | e.g. `active` |
| `local_path` | TEXT | Relative path |

### `technicians`
`technician_id` (PK), `shop_id`, `role`, `hourly_rate`.

### `aircraft`
`aircraft_id` (PK), `registration` (synthetic, never a real registration),
`fleet_type`, `year_built`.

### `engines`
`engine_id` (PK), `aircraft_id` (FK→aircraft), `shop_id`, `part_family`, `install_date`.

### `inventory_parts`
`part_id` (PK), `part_number`, `part_family`, `shop_id`, `unit_cost`,
`lead_time_days`, `lead_time_std_days`, `current_stock`, `is_synthetic`.

### `maintenance_orders`
`order_id` (PK), `aircraft_id` (FK), `engine_id` (FK), `technician_id` (FK),
`part_id` (FK), `order_date`, `order_type`, `status`, `labor_hours`, `downtime_hours`.

### `inventory_transactions`
`txn_id` (PK), `part_id` (FK), `order_id` (FK), `txn_date`, `quantity`, `unit_cost`, `txn_type`.

### `downtime_events`
`event_id` (PK), `aircraft_id` (FK), `order_id` (FK), `start_time`, `end_time`,
`downtime_hours`, `cost_per_hour`.

### `ingestion_runs`
`run_id` (PK), `source_id` (FK), `run_timestamp`, `file_name`, `rows_ingested`,
`checksum`, `status`.

### `engine_predictions`
`prediction_id` (PK), `engine_id` (FK), `model_name`, `model_version`,
`predicted_rul`, `actual_rul`, `prediction_date`.

### `anomaly_results`
`result_id` (PK), `engine_id` (FK), `model_name`, `anomaly_score`, `is_anomaly`,
`threshold`, `run_date`.

### `model_registry` (SRS §11 / FR-14)
`model_id` (PK), `model_name`, `version`, `algorithm`, `dataset_fingerprint`,
`features_json`, `params_json`, `metrics_json`, `random_seed`, `artifact_path`,
`training_date`, `notes`.

### `experiments`
`experiment_id` (PK), `model_name`, `run_date`, `params_json`, `metrics_json`, `notes`.

## 4. Analytical Parquet tables (`data/processed/`)

### `maintenance_demand.parquet` (forecasting input)
| Column | Type | Definition |
|---|---|---|
| `date` | datetime | Week date |
| `shop_id` | string | Maintenance shop |
| `part_family` | string | Part family |
| `demand_count` | int | Weekly maintenance demand (count) |

Chronological splits add `week_num`: `train.parquet`, `validation.parquet`,
`test.parquet`, `future_buffer.parquet`.

### `inventory_data.parquet`
`part_number`, `part_family`, `shop_id`, `current_stock`, `unit_cost`,
`lead_time_days`, `lead_time_std_days`, `demand_mean_weekly`, `demand_std_weekly`,
`service_level_target`, `criticality`, `source`.

### Financial inputs
| File | Columns |
|---|---|
| `financial_fleet.parquet` | `fleet_type`, `aircraft_count`, `avg_annual_flight_hours_per_aircraft`, `total_annual_flight_hours`, `revenue_per_flight_hour`, `total_annual_revenue_potential`, `source` |
| `financial_shop_labor.parquet` | `shop_id`, `base_labor_rate`, `overtime_labor_rate`, `technician_count`, `annual_regular_capacity_hours`, `annual_overtime_capacity_hours`, `total_annual_capacity_hours`, `source` |
| `financial_maintenance_labor.parquet` | `shop_id`, `part_family`, `mean_labor_hours_per_job`, `labor_cost_per_job`, `labor_rate_used`, `source` |
| `financial_downtime_costs.parquet` | `fleet_type`, `part_family`, `mean_downtime_hours`, `downtime_cost_per_hour`, `downtime_cost_per_event`, `source` |
| `financial_inventory_cost_params.parquet` | `holding_cost_rate`, `stockout_cost_multiplier`, `order_cost`, `currency`, `source` |

Every analytical table carries a `source` column recording provenance
(`synthetic_mro`, `synthetic_inventory`, `synthetic_financial`, `nasa`).
